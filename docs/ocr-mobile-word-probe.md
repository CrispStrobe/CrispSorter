# Android reviewed Word export qualification

The existing `scripts/mobile_ocr_webview_smoke.mjs` gate includes a bounded Word
export observation in the real installed Android application. It requires the
`ocr-mobile` build to advertise `docx_export` and the `docx` output format. It uses
the same exact application, native library, installed APK and model identities
recorded by that gate. Defining this observation does not establish that a target
run has passed; retain the run's `receipt.json` and generated artifacts to report
the actual result.

After native recognition and the repeated inference observations, the probe adds
one separate review page to its existing synthetic project. It changes the exact
recognized value `2048` to `2049` and appends one explicitly authored paragraph
containing Hebrew and Arabic marks, Latin text, digits, a tab, and leading and
trailing spaces. This is an automated manual-review fixture, not human review or
a multilingual OCR accuracy observation. The original recognized pages and raw
native results must remain unchanged.

The probe saves the review with the current project revision, loads it again,
compares the persisted state, and sends that loaded page through the native
`ocr_workspace_export` command. It retains the private `.docx` bytes before
checking the returned metadata. A separate Python ZIP and XML reader checks the
Word package type and relationships, archive integrity, exact logical paragraph
text and ordering, whitespace preservation, and the mixed paragraph's RTL
property. CR, LF and CRLF each become a paragraph boundary, matching the Word
export contract. No Unicode normalization or visual reordering is accepted.

The successful path then discards the private export and verifies that its
individual staging directory is gone. If generation or validation fails, the
probe retains the expected review and any generated bytes it can read, with a
separate ten-second recovery budget. The original error remains fatal. General
probe cleanup still attempts to discard staging after a failure.

## Retained evidence

- `synthetic-reviewed-word-state.json`: reloaded review page and revision, exact
  expected paragraphs, raw-recognition hash, and unchanged-original assertions.
- `synthetic-reviewed.docx`: bytes generated by the application, retained before
  package or content assertions.
- `synthetic-reviewed-word-readback.json`: independent package/text observation,
  document and XML hashes, paragraph direction properties, and explicit scope.
- `synthetic-reviewed-word-reader-process.json`: reader process diagnostics when
  the independent check fails.
- `receipt.json`: the Word stage result, actual source identities from the parent
  probe, output hash/size, and staging cleanup outcome.

The reader caps its archive at 16 MiB, total uncompressed content at 32 MiB, each
XML part at 8 MiB, and expected paragraphs at 100. Its six focused controls reject
changed corrections, lost marks, reordered paragraphs, missing RTL or whitespace
properties, duplicate/truncated/wrong-type packages, excessive expansion, and
DTD/entity declarations. These reader controls do not execute the application.

This gate qualifies native generation, persisted logical text, package structure
and private staging cleanup only when the actual target run passes. It does not
open a Word application, validate visual pagination, exercise the system save
picker or provider transfer, or certify a physical device. The separate
`ocr_text_export::tests` filter in the paired application gate compiles and tests
the production text module against the complete application dependency graph.
